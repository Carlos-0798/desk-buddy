定位
本软件管理 Desk Buddy 原型机，可选择 USB CDC 串口或已配对设备的 BLE GATT 管理连接。
R5 支持通过 BLE 读取状态、编辑/预览/保存三套配置与按键/外观、动作试播及还原。
管理连接与 USB/BLE 媒体键/键盘 HID 输出是两个独立选择，连接 Hub 不会自动开启 HID。
电池供电时，已建立的 BLE 管理连接可以在拔掉 USB 后继续使用；仅 USB 管理会随拔线断开。
本软件不需要账号、云服务、管理员权限或开机自启。

启动
1. 解压完整 Windows 发布包到普通本地文件夹。
2. 双击 DeskBuddy.Hub.exe。首次启动不会自动开启设备输出。
3. 管理连接选择“USB 线缆”，重新检测并选择 Desk Buddy 的 COM 端口后连接。
4. 如果出现端口占用，关闭 Arduino 串口监视器或其它测试程序，再重试。
5. 若看到旧版 R2C，基本状态仍可读；配置编辑需要 R3，新增主题/角色/主页模式需要 R3A。
   Hub 不自动刷写固件。不要用其它型号的固件或擦除校准/配对数据。
用户已确认本机双击能打开 Hub；签名暂不处理，不影响正常本地开发与交付。
R3D4 自动检查已通过；人工五项及尚未完成的 GUI 还原/撤权提示/断开重连仍需验证，进度以本轮测试报告为准。

BLE 管理连接
1. 先确认 Desk Buddy 已在 Windows 蓝牙设置中配对；已有配对无需删除重建。
2. 在小屏“菜单 → 设备信息 → 蓝牙管理 → 允许蓝牙连接”打开最长 60 秒连接窗口；
   或在 USB 管理中点“通过 USB 允许 BLE”。这一步会关闭 HID 输出。
3. 断开当前 USB 管理（可保留 USB 供电），管理连接选“蓝牙 LE · 已配对设备”，
   重新检测、选择自己的 Desk Buddy，再连接。成功后显示 BLE GATT 管理。
4. 连接采用加密链路、已绑定设备与设备端管理授权；配对本身不等于管理授权。
5. 开始管理后连续 15 秒没有成功请求会撤权。正常 Hub 轮询保持会话；
   断开、睡眠或异常后重新在设备端授权，再手动重连，不重放旧操作。
这些是 R5 的使用流程；最终硬件能否正常执行仍以本轮发布状态和测试报告为准。

页面

控制配置：K1–K6、顺转、逆转、旋钮按压、三个触屏键，共 12 个映射。

配置的三个阶段
编辑只改变电脑上的草稿。
预览把草稿应用到设备内存，不写入 Flash；设备输出会关闭。
保存才把完整配置写入设备，并读取确认；设备输出也会关闭。
预览/保存会提交全部三套配置，并把当前正在编辑的页签设为设备活动配置。
还原恢复设备最后保存的配置。未保存预览在设备断电/重启后丢失。
发生版本冲突时先重新读取设备；Hub 不会在重连时偷偷覆盖设备。
MEDIA / STUDY / WORK 是三套独立保存的配置，不是会自动识别应用的智能模式。
出厂按键映射完全相同；切换名称本身不会自动改变用途。
MEDIA：建议配置播放、切歌、音量；STUDY：建议配置学习常用快捷键；WORK：建议配置工作软件快捷键。
这些只是使用建议，快捷键须由你在“控制配置”页设置；每套外观也可以不同。
它们与“表情面板 / 桌面伙伴 / 电子宠物”这三个显示模式是两回事。
当前配置名称使用 1–15 个 ASCII 字符；Hub 和屏幕界面可以使用中文或英文。
中文界面不受此限制；板载配置名称本身暂不支持中文。
导入/导出的是整个三配置集合；不包含触摸校准、蓝牙配对信息或任何执行脚本。

新的海洋、落日、花园、蓝图主题带有各自背景细节；兔子、幽灵、团子、太空伙伴、
狐狸、熊猫等采用有明暗、服饰和轮廓细节的原创像素游戏角色素材。
完整角色含待机、眨眼、开心、两帧迈步；幽灵以尾部摆动对应迈步。

30秒无有效实物输入后闭眼显示Zzz；下一次输入唤醒，原有绑定仍照常执行。

动作区旁边直接显示动画。未连接设备时只在电脑预览；连接支持该功能的R3C后可同步小屏。
同步试播会先把当前草稿临时应用到设备，并关闭输出，再播放动作；不会保存到Flash。

明确点击动作时临时播放动画，即使“日常动画”关闭；不会改变该开关的保存值。
设备的按键/旋钮/有效触摸会结束试播；原有绑定仍按当时输出状态执行。

本轮桌宠在设备屏幕上，不是 Windows 桌面悬浮窗；没有喂养、经验值或成长存档。

按键能力
支持播放暂停、上一曲、下一曲、静音、音量加减；
支持一个标准键盘键加 Ctrl/Shift/Alt/GUI 修饰键的一次按下/松开；
左/右修饰键独立保留；GUI 在 Windows 上对应 Win 键。
支持打开菜单、记录标记、关闭输出、切换下一配置等设备本地动作。
不包含多步宏、长按保持或任意运行电脑程序的能力。
触屏按键的标签随映射调整，不应把已重映射的按钮当作原有媒体键。
主板 USER SW 长按约两秒关闭输出，独立于自定义映射。

连接和恢复
USB/BLE 管理连接负责 Hub 读写设置；USB/BLE HID 通道负责设备操作电脑，分别选择。
切换通道或修改配置后，请确认映射再主动开启输出。
关闭 Hub 不等于停止设备独立工作；要停止操作电脑，先关闭设备输出。
Windows 休眠、拔线或端口异常后，界面必须先恢复新鲜状态再允许操作。
不要同时运行两个 Hub 实例争用同一串口。
BLE 正常断开会请求并核对管理撤权，不改变原 HID 输出状态；退出 Hub 不等于关闭媒体输出。
若撤权/退订未获确认，软件会报告失败；在设备端撤销或停止管理请求并等待空闲超时。
另一管理端正在修改设备时可能返回 BUSY；不要反复发送写入。配置版本冲突返回 STALE，先重新读回。
显示未知或过期状态时，先检查连接，不应将旧数字当作当前测量。

电池显示的边界
百分比是根据电压作出的粗略估计，不是电量计芯片测得的真实剩余容量。
USB 供电状态不能证明正在充电，Hub 也不能测量电池温度、充电电流或实际续航。

本版不含
前台应用自动配置切换、云同步、任意图片/GIF皮肤上传、手机 App、无线固件升级或自动固件升级。
这些限制不影响设备离线执行已保存的媒体键/热键配置。

开发
源代码：DeskBuddy.Core（协议/配置/文件/有界BLE分片），DeskBuddy.App（WPF/USB串口/Windows BLE GATT/界面）。
协议定义见 PROTOCOL.md；固件位于 ../firmware/DeskController。
Windows x64 + .NET 10 SDK 可构建；发布包自带运行时，最终用户无需单独安装 SDK。
Core.Tests 为主机测试，不冒充实物按压、显示外观或电池断电验收。
具体本轮自动测试结果和待人工项目见发布目录 TEST-REPORT 与 MANUAL-CHECKLIST。
项目根目录执行 hub/build.ps1 -Publish，默认输出 outputs/hub-r5/windows；不自动启动应用。
可选签名工具独立于本地发布，说明在 outputs/hub-r5/signing；当前没有宣称可信签名发布。

调试与本地演示
在已打开的命令行中运行 DeskBuddy.Hub.exe --demo 可进入明确标注的演示模式，
它不访问实物串口或蓝牙。正常使用请直接双击 EXE，不加 --demo。
--render-smoke <输出目录> 只做离线测试；--device-smoke 会访问实物，仅供测试使用。
